## Engine.IO WebSocket fragment DoS candidate — scoped patch pending hosted checks

The [pnpm audit after PR #30](https://github.com/GoreeCloud/photos/actions/runs/42536722363) reports high GHSA-96hv-2xvq-fx4p affecting ws 8.20.1. Lockfile tracing identifies its only vulnerable edge as **engine.io-client 6.6.5 → ws 8.20.1**. Other inherited consumers already use ws 8.21.3 and 8.22.1; a separate webpack-bundle-analyzer path still uses ws 7.5.12. A blanket 8.x override unnecessarily downgrades those newer WebSocket versions, so it is prohibited here.

The official [websockets/ws 8.20.1→8.21.3 change history](https://github.com/websockets/ws/compare/8.20.1...8.21.3), published manifests and MIT license were inspected. Upstream added receiver limits for empty message fragments, test fixtures for fragmented control, and permessage-deflate validation. The newer 8.21.3 version already exists in the inherited lockfile, shares the Node >=10 minimum, and does not require a new runtime dependency or an installer script.

The candidate uses **parent-scoped pnpm override engine.io-client>ws to 8.21.3**, replacing only the vulnerable package's one parent edge. The lockfile preserves ws 7.5.12, 8.21.3 and 8.22.1 at their existing parents, and removes only the old ws 8.20.1 package snapshot. The initial attempted broader version selector was **rejected before publication** because it silently downgraded three unrelated 8.22.1 edges; the candidate was regenerated from an unmodified base lockfile and the exact parent-specific diff was rechecked.

A small **synthetic, bounded** receiver check is added to the already registered, owner-triggered E2E typecheck workflow. It feeds a nonfinal empty binary frame plus two empty continuation frames to ws Receiver configured with maxFragments=2 and checks for an explicit RangeError/WS_ERR_TOO_MANY_BUFFERED_PARTS. It uses Node buffers, no network, no private photo data and no application service. Official upstream [receiver regression source](https://github.com/websockets/ws/blob/8.21.3/test/receiver.test.js) documents this same edge case. This is not a full WebSocket auth or availability load test.

Acceptance requires local source/lockfile checks, exact-head GitHub source integrity, the synthetic receiver check and E2E TypeScript, frozen docs/web/server builds and a full/production pnpm advisory rescan. Even if the relevant high finding disappears, remaining high/moderate findings and application auth/photography/privacy release gates remain open.
